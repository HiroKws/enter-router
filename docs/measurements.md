# 連続 Enter の窓は実測で決めた（measurements）

このファイルは「なぜ 250ms なのか」を、**この環境の実測値**で示すための記録です。
設計値でも一般論でもありません。測ったのは 2026-10-28、対象はオペレータ本人の打鍵です。

## 1. 何を測ったか

状態機械が「連続」と見なす条件は、**keyup を挟んだ Enter down の間隔**です
（OS のキーリピートは keyup を挟まないので数えません。design §3.6 / research §2-d）。
したがって測るべきは次の 2 つだけです。

| 種類 | 意味 | 窓との関係 |
|---|---|---|
| 連続（burst） | 「2 連打 / 3 連打」のつもりで叩いたときの間隔 | 窓は**これより広い**必要がある（狭いと 2 連打が 2 回の単発に割れる） |
| 非連続（separated） | 「別々の操作」のつもりで間をあけたときの間隔 | 窓は**これより狭い**必要がある（広いと別操作が 1 回の送信に融合する） |

## 2. どう測ったか

`scripts/measure_enter.py`（Windows 実機・実キーボード）。
`WH_KEYBOARD_LL` フックで `VK_RETURN` の keydown 時刻だけを記録し（本文は取らない、
キーは一切飲み込まない）、区間ごとに JSON へ落とす。3 段階:

1. 2 連打 ×5 セット（セット間は 1 秒以上あける）→ 1→2 の間隔
2. 3 連打 ×3 セット → 2→3 の間隔
3. **別の操作として**間をあけて 6 回 → 非連続の間隔

生データ: `%USERPROFILE%\enter-measure.json`（`phases` は keydown の時刻そのまま、
`gaps` は区間内の差、`calibration` は後述の計算結果）。

## 3. 実測値

### 連続（burst）

ツールでの計測（15 サンプル、単位 ms）:

```
double: 157, 157, 157, 157, 180
triple: 112, 180, 135, 158, 135, 134, 159, 157, 158, 158
→ 112, 134, 135, 135, 157, 157, 157, 157, 157, 158, 158, 158, 159, 180, 180
```

同じフックが残した**実際の常用ログ**（`%APPDATA%\enter-router\logs\enter-router.log`
の `hold_start` → `hold_extend` の差、9 サンプル）:

```
96, 113, 135, 135, 135, 135, 136, 157, 201
```

合わせて **24 サンプル、96〜201ms**。最も遅い連続は **201ms**。

### 非連続（separated）

```
495, 540, 585, 585, 585
```

5 サンプル、**495〜585ms**（1 秒を意識せず、本人の「連続ではない」普通の速度）。
最も速い非連続は **495ms**。

## 4. 決め方（`core/calibrate.py`）

```
want    = 最も遅い連続 × 1.25 = 201 × 1.25 = 251ms
ceiling = 最も速い非連続 × 0.80 = 495 × 0.80 = 396ms
want <= ceiling なので want を採用 → 10ms に丸めて 250ms
```

結果: **`hold_window_ms` = `triple_enter_window_ms` = 250ms**
（最も遅い 2 連打の 49ms 上、最も速い「別操作」の 245ms 下。両側に余裕があります）。

丸めと範囲（120〜600、`core/config.py` の検証と同じ）は `recommend_window()` が行い、
`ok` / `note` に「クラスタが分離しているか」を残します。**分離していない（重なった）測定は
`ok=False` として警告**し、黙って使わせません。

## 5. 何が変わるか

- 単発 Enter の最大遅延が 350 → **250ms**（体感で速くなる）
- 2 連打の判定窓が 350 → 250ms（**それでも本人の最遅 201ms を包含**）
- 3 連打の判定窓は 250ms のまま。ただし **3 発目は「4 発目が来ないこと」を 250ms だけ
  待ってから発火**するようになりました（4 連打以上の取り消しのため。design §3.4）
- 4 連打以上は**キャンセル**（改行も送信も hermes も出さない。入力欄のテキストは保持）

## 6. 再測定のしかた

窓が合わないと感じたら（例: 2 連打が送信にならず 2 改行になる）、同じツールで測り直します。

```
python.exe <repo>\scripts\measure_enter.py --out C:\Users\<you>\enter-measure.json
```

`--only separate` で 1 段階だけ測り直せます（他の段階の記録は保持）。
結果の `calibration.window_ms` を `policy.hold_window_ms` と `policy.triple_enter_window_ms`
の両方に入れてください（UI の設定画面からも変更できます）。
